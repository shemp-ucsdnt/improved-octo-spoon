# Threads of Fate — Build State Summary

*Written for review in a separate Claude conversation that has no context on this project — everything needed to evaluate the current state should be self-contained below.*

## What this is

A from-scratch Unity C# implementation of the gameplay systems for an original action-RPG, "Threads of Fate," built from a design spec (a PDF the user provided) describing three playable characters:

- **Rue** — monster shapeshifting (collects "Monster Coins," transforms into forms with different physics/hitboxes/environment abilities).
- **Mint** — elemental magic (combines a Color + an Effect into a spell; colors also trigger fixed world interactions).
- **Kaelen** — summons "constructs" from an elemental thread inventory, each with continuous MP upkeep, an Overclock attack, and a Deconstruct utility.

No art, no levels, no animation — this is purely the mechanical/systems layer, validated through a single procedurally-built test arena (built entirely by a script at runtime, no authored Unity scene file).

## Critical caveat: this has never been compiled or run

**Unity Hub doesn't run on the development Mac (macOS 12.6.3)**, so there's been no way to install/launch a Unity Editor and no Unity project has actually opened this code. Every file below was hand-written and hand-reviewed (cross-references checked, braces balanced, method signatures matched by inspection) but never opened in the Unity Editor, never compiled, never played. Treat correctness as "carefully reasoned," not "verified." The most likely failure modes are: Unity API misuse that only a compiler would catch, and physics/trigger behavior (`CharacterController` + trigger interactions, `Physics.Raycast` reflection) that depends on exact runtime behavior no static review can confirm.

## Core (shared foundation)

- `IDamageable` — `ApplyDamage(amount, sourceTag)` / `ApplyHeal(amount)`.
- `CharacterVitals` — per-character HP + MP. **Each of Rue/Mint/Kaelen owns an independent instance** — pools are never shared. No passive MP regen (Mint's regen is combo-driven by design; nothing else specified passive regen).
- `EffectType` (Damage/Heal) + `EffectResolver.Apply()` — the one shared function that turns "a number + a type" into an actual `IDamageable` call.
- `MeleeComboComponent` — generic combo-chain tracker (hit count + reset timer), shared by Mint's ring-blades and Kaelen's whip-dagger.
- `IStatusAffectable` — minimal status-flag set/clear (no durations/stacking — deliberately minimal), implemented by `CharacterVitals`.
- `CharacterSwitchController` + `SwapStation` — **location-gated character switching**. Only one character is controlled at a time; switching control is only permitted while the active character is within range of a `SwapStation` (dungeon entrance, NPC hub, etc.) — not freely, anywhere. Switching never moves anyone.
- `CharacterMovementController` — real WASD+jump movement via Unity's `CharacterController`, world-space (not camera-relative, kept simple deliberately). Exposes `SetPhysicsOverride()`/`ClearPhysicsOverride()` so Rue's transformation system can swap gravity/jump/speed/hitbox dimensions per form.
- `CameraFollow` — simple offset follow-camera, retargets automatically when the active character changes.
- `EnvironmentInterfaces.cs` — `IHeavySwitch` (BodyWeight), `INarrowPassage` (BodySize), `IHazardFlight` (CanFlyOverHazard): capability-query interfaces environment objects use to gate passage. Only Rue's forms implement them today, but nothing ties them to Rue specifically.

## Kaelen — Soul Constructing Architecture

- `ThreadInventoryComponent` — all-or-nothing consume/refund over 8 elemental thread types.
- `ConstructDeploymentManager` — deploy/Overclock/Deconstruct; continuous MP drain per tick across all active constructs; **auto-Deconstructs everything if MP hits 0**; now actually spawns a placeholder (or prefab) visual per deployed construct.
- `KaelenResourcePool` — MP delegates to the character's own `CharacterVitals`; owns Kinetic Energy, generated by `KaelenComboKineticGenerator` off melee-combo hits (previously only ever consumed by Overclock).
- **5 constructs**, each with a non-empty (illustrative) thread recipe: Phlogiston Boiler, Tidal Conduit, Mist Weaver (MP-drain + Overclock damage + Deconstruct utility), plus two utility constructs added later:
  - `AggroDecoy` (Umbral Decoy) — a marker component; there's no enemy AI yet to actually redirect, so this is a hook for later, not a working redirect.
  - `PrismTurretBeam` + `PrismMirror` + `IPrismReceiver` — a real raycast-and-reflect laser puzzle (bounces off mirrors, triggers a receiver). **The mirror/receiver placement in the test map is an unverified geometry guess.**
- `CleansingFogUtility` — clears `IStatusAffectable` statuses in a radius.

## Mint — Elemental Spell Synthesis

- `SpellCombinationFactory` — O(1) lookup: (Color, Effect) → `SpellDefinition` (name, MP cost, damage/heal + magnitude).
- Colors are a closed 4-value enum, each fixed to a world-interaction tag (Red→ignite, Blue→freeze, Green→drive-turbine, Black→shatter) regardless of which Effect was cast. Effects are an open string set.
- `MintComboMPRegen` — combo hits restore MP (spec explicitly ties Mint's regen to melee combos, not time).
- Spell matrix: 8 illustrative rows (every color × Burner/Restore) — not a designer-authored final list.

## Rue — Monster Shapeshifting (built entirely in this pass, previously nonexistent)

- `MonsterCoinQueue` — strict 5-slot FIFO; a 6th `Collect()` evicts the oldest.
- `MonsterFormDefinition` — per-form data: gravity scale, jump height, move-speed multiplier, fly flag, `CharacterController` height/radius (hitbox swap), body weight/size (feeds the environment interfaces), continuous MP drain rate, one discrete ability + cost.
- `RueTransformationController` — `TransformInto(formId)` (requires currently *holding* that form's coin — an interpretation, since the spec describes the coin queue but not exactly how holding a coin relates to transforming), continuous MP drain while transformed (auto-reverts to base form at 0 MP, mirroring Kaelen's pattern), discrete ability use, and implements the three environment interfaces from current-form state.
- Four forms modeled: Saber Tiger, Stinger (flies), Clay Golem (heavy — trips `IHeavySwitch`), Mandragora (small — fits `INarrowPassage`).

## World (reusable level mechanics, not test-only)

`ElementalTrigger` (color-reactive world objects) and `Rotator` live here — promoted out of the test-map folder because they're real level mechanics any future level would place, not scaffolding. `ElementalTrigger` fires an `OnActivated` event other pieces react to:

- `ActivationGate` — generic "remove an obstacle" gate.
- `FreezeWalkway` — before Blue is cast: a solid invisible blocker prevents crossing the water; after: a flush walkable ice platform replaces it. A real traversal puzzle, not a cosmetic color swap.
- `TurbinePlatform` — raises a connected bridge when Green engages it.
- `HeavySwitchPlate`, `NarrowPassageGate`, `HazardZone` — Rue's three environment pieces, gated by the interfaces above.

## Test map

`TestMapBuilder` builds the entire arena from code at `Start()` — ground, camera+light, 4 elemental stations with real consequences, 5 construct deploy pads, a `TargetDummy` (takes real damage/heals), Rue's 3 environment pieces + the Prism Turret puzzle, and all three characters (independent HP/MP, movement, kit-specific input). Rue starts pre-seeded with all 4 coins since there's no monster-defeat/pickup system yet to earn them legitimately.

Full control scheme (documented in the file's header comment): WASD+Space to move/jump; F1/F2/F3 to switch characters (only works near the gold "NPC Hub" disc); Mint uses 1-4 (+Shift for the Restore variant) to cast and Left Mouse to build combo; Kaelen uses E/R/T/Y/U to deploy, G/H/J to Overclock, Z/X/C/V/B to Deconstruct, Left Mouse to build combo (keys were remapped off WASD once movement was added); Rue uses 1-4 to transform, 0 to revert, Left Mouse to use the current form's ability.

## What's deliberately NOT built (explicit gaps, not oversights)

- Enemy AI — nothing exists to fight, to redirect via `AggroDecoy`, or to test `IHazardFlight`/`IHeavySwitch` against in a real combat scenario.
- Animation — everything is Unity primitives (capsules, cubes, cylinders).
- UI/HUD — all feedback is `Debug.Log` console output.
- Save/load, audio/VFX (though Observer-pattern hooks like `OnConstructDeployed`, `OnFormChanged`, `ElementalTrigger.OnActivated` were built specifically so audio/VFX can attach later without touching core logic).
- Real, designer-balanced numeric data — every stat/recipe/magnitude in the codebase is explicitly flagged as illustrative test data, not final design.

## The immediate blocker

**Unity Hub doesn't run on this Mac (macOS 12.6.3)** — that's the specific piece that's broken, not necessarily the Unity Editor itself. Either way, there's currently no way to compile-check, open in the Editor, or build a WebGL export locally on this machine. The plan going forward: produce a WebGL build on another machine or a cloud build service, then serve that build's output locally for play-testing. Nothing in the WebGL pipeline itself has been started — this summary exists so a fresh reviewer (or a different Claude session) can assess whether the code as described is sound enough to be worth building, and flag anything that looks wrong before spending a build cycle on it.
